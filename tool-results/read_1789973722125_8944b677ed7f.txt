    23→1. اول از همه: سیستم Authorization مرکزی
    24→
    25→این مهم‌ترین تغییر پروژه است.
    26→
    27→الان بعضی APIها requireAuth دارند، بعضی ندارند.
    28→
    29→مثلاً:
    30→
    31→/api/profile
    32→/api/prepay
    33→
    34→از requireAuth استفاده می‌کنند، اما بسیاری از این‌ها نه:
    35→
    36→/api/vehicles
    37→/api/jobs
    38→/api/invoices
    39→/api/messages
    40→/api/notifications
    41→/api/admin/*
    42→/api/wallets
    43→/api/reviews
    44→/api/referral
    45→/api/insurance
    46→...
    47→
    48→این نباید این‌طور باشد.
    49→
    50→باید یک سیستم مرکزی داشته باشیم:
    51→requireAuth()
    52→requireRole("ADMIN")
    53→requireRole("TECHNICIAN")
    54→requireRole("CUSTOMER")
    55→
    56→requireOwnership()
    57→requireJobParticipant()
    58→requireVehicleOwner()
    59→requireInvoiceAccess()
    60→
    61→مثلاً:
    62→
    63→const session = await requireAuth(req);
    64→
    65→if (session instanceof NextResponse) {
    66→  return session;
    67→}
    68→
    69→بعد:
    70→
    71→requireRole(session, "ADMIN")
    72→
    73→یا:
    74→
    75→requireRole(session, ["ADMIN", "TECHNICIAN"])
    76→
    77→اصل مهم این است که Default باید Deny باشد؛ یعنی API تا وقتی صراحتاً اجازه‌ای تعریف نشده، دسترسی ندهد. این دقیقاً با توصیه OWASP برای Function-Level Authorization منطبق است.

    79→2. مالکیت Objectها باید کامل شود
    80→
    81→این یکی از جدی‌ترین مشکلات فعلی است.

    83→مثلاً الان API خودرو می‌تواند چیزی شبیه این دریافت کند:

    90→

    92→
    93→نباید.
    94→
    95→باید از Session بفهمیم:
    96→
    97→session.userId
    98→        ↓
    99→Customer
   100→        ↓
   101→Vehicle
   102→
   103→مثلاً:
   104→
   105→const customer = await db.customer.findUnique({
   106→  where: {
   107→    userId: session.userId

   110→
   111→و بعد:

   113→where: {
   114→  id: vehicleId,
